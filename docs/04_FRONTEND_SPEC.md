# 04 - Frontend Spec

## Stack (decision D-10)

| Part | Choice | Source to follow |
|---|---|---|
| Framework | Next.js (App Router) + TypeScript | `ShoeSafari-Org__ShoeSafari` (Next.js + Stellar) |
| Styling | Tailwind CSS | ShoeSafari |
| Wallet | Stellar Wallets Kit, package `@creit-tech/stellar-wallets-kit` installed with `npx jsr add @creit-tech/stellar-wallets-kit` | `Creit-Tech__Stellar-Wallets-Kit/README.md` and its `examples/nextjs` |
| Contract client | TypeScript bindings generated by the Stellar CLI from the deployed contract | `stellar contract bindings typescript --help` |
| Bs ramp (phase 4) | `@pollar/core` / `@pollar/react` | `05_INTEGRATIONS.md` |

Versions: install current versions with the package manager and record them in `PROGRESS.md`. Do not pin versions from memory.

```
frontend/
  .env.example
  src/
    app/
      page.tsx                     Home
      dashboard/page.tsx           My agreements
      agreements/new/page.tsx      Create agreement
      agreements/[id]/page.tsx     Agreement detail + actions
      arbiter/page.tsx             Disputed milestones
    components/
      WalletButton.tsx
      AgreementCard.tsx
      MilestoneRow.tsx             status badge + role-based action buttons
      MoneyLocked.tsx              locked amount + block explorer link
      TxStatus.tsx                 pending / success / error for a transaction
    lib/
      config.ts                    reads env vars, fails loudly if missing
      wallet.ts                    Stellar Wallets Kit wrapper

    contracts/escrow/              generated bindings (do not edit by hand)
```

## Behaviour rules

- Role is derived from the connected address: freelancer, client, arbiter or viewer. Show only the actions allowed for that role and milestone status (`03_CONTRACT_SPEC.md` section 1).
- Amounts: users type decimals (for example 150.50); convert to the 7-decimal integer in `format.ts`; show decimals everywhere.
- Every money screen shows the locked amount and a link to the contract on the block explorer ("see the money").
- Show the platform fee and the net amount the freelancer will receive before creating an agreement and before approving.
- Show the review window as a date and a countdown after submission.
- After each transaction, re-read state from the contract; never assume success.
- Errors: map contract error codes (`contracts/escrow/src/errors.rs`) to plain messages.
- UI language: decision D-11.
